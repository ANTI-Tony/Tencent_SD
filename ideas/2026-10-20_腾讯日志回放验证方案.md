# 腾讯日志回放验证方案（2026-10-20 草案）

前提：腾讯不能把模块接进线上，只能拿历史日志在一台 8×H20 上模拟。本文回答：要多少数据、跑多久、花多少、想讲什么故事、想得到什么结果。机时都是估算，第零层标定后修正。

## 1. 两层模拟

历史日志是现成的，抓完就能开始，不用按真实时间等。但每个 token 都要让目标模型重算一遍：草稿头训练要目标模型的 aux hidden states，日志里只有文字。所以**机时 ∝ 处理的 token 总量，与日志跨几个月无关**；重算的工作量和线上当初差不多（线上一群机器算几个月，回放只有一台）。

- **第零层 标定（0.5–1 天）**：H20 上扫"并发 {1,4,8,16,32,64,128,256} × 投机开/关 × 出厂头/适应头"的吞吐，拟合 gain(a,C)=a·T_base(C)/T_spec(C)。H100 上已验证：对接受长度线性（残差 ≤0.03），热替换闭环预测 +26%、实测 +24%。
- **第一层 离线算账（覆盖全部日志，全量或抽样）**：日志里的真实输出 + 目标模型预填充（teacher forcing）得到 aux hidden states；每个草稿头逐步模拟 k 步链式草稿与验收（贪心解码下精确；采样解码用 Σmin(p,q) 期望接受率，第二层核对）。在线头按到达顺序"先考再学"（prequential：先评估再训练，杜绝 10-08 提示池循环那种记忆泄漏）。对照：现网固定头、按腾讯现行频率离线重训的头。几种头共用一次目标模型计算。产出：每天 × 产品线的接受长度曲线、变化事件后的恢复时间；再用第零层曲线 + 每分钟负载换算成吞吐。
- **第二层 闭环回放（3 天日志，抽稀 + 加速）**：vLLM + live tap + 训练进程 + 控制器 + 热替换；按原始到达顺序回放一台机器的线上份额（按会话哈希切），不按真实时间：抽稀 1/k 再 k 倍速（例 k=4），单机负载 = 线上，3 天日志 18 h 放完。三组同流量：A 现网配置；B 只开投机开关（控制器规则 1）；C 完整系统。产出：吞吐、p99 TTFT/TPOT、SLO 违约、占空比、换头次数；检验第一层换算（R4）。代价：高峰低谷压短 k 倍，"闲时训练"失真；腾讯要看这部分可加跑 1 天真实时间。

## 2. 数据需求

- 时间范围：抓过去 3 个月（现成数据，不用等），最少 1 个月；能多抓更好——抓几个月不影响机时，6 个月能多赶上几次换代。理由：看到草稿头变旧要时间；要包含 1–2 个真实变化事件（模型换代 / 新业务 / 提示词改版 / 节假日）；12 个周周期做配对统计。
- 全量还是抽样看总量。一台 8×H20 一天能处理（含开销）：8B 约 17 亿 token、30B-A3B 约 26 亿、A13B 6–13 亿、DeepSeek-V3 级约 4.6 亿 → 口径"中小模型 10–20 亿/天、大 MoE 约 5 亿/天"。

| 日志总量 | 中小模型 | 大 MoE |
|---|---|---|
| 20 亿 token | 1–2 天 | 约 4 天 |
| 100 亿 token | 5–10 天 | 约 20 天 |
| 1000 亿 token | 50–100 天 | 约 200 天 |

- 量小（全量跑完不超过几天）→ 全量；量大 → 按产品线 × 小时分层抽，每天 5千–1万条，三个月约 10–20 亿 token（2k token/条）；事件日加到 5 万条（看小时级恢复）。依据：新领域学 3200 条到顶、单遍更新 3200 条 7 GPU 秒（H100）；Aurora 从零约 1 万请求收敛。抽样让在线头学得比线上慢 → 增益偏保守。**第一件要问腾讯：三个月总共多少条请求、每条平均多长。**
- 第二层：3 天（普通工作日、周末、事件日）完整日志，按会话切一台机器份额，保留原始到达时间；回放时再抽稀加速。
- 聚合表：三个月全量每分钟请求数 + 输入/输出 token 数（按产品线）+ 线上同模型机器数。
- 每条字段：到达时间、会话哈希、产品线、完整输入（system + 多轮历史，最好 token id）、完整输出、采样参数、模型版本。
- 配置：现网草稿头权重 + 训练配方 + 重训频率；推理引擎与版本、投机参数（k、按 batch 的 k 表）；SLO；单机最大并发；H20 96G/141G；三个月内换代 / 上线 / 改版时间点。
- 硬前提：输出须由同版本目标模型生成；换代按版本切开（换代日是最佳实验点）；输出来自已下线模型 → 重新生成，第一层机时约翻倍。
- 隐状态不落盘（8B 每 token 约 25 KB，三个月几十 TB），边算边用。

## 3. 机时与成本（单台 8×H20，按第一层 10–20 亿 token 即抽样情形）

| | 中小模型（单副本 ≤2 卡：8B 稠密、30B-A3B、A13B） | 大 MoE（单副本 8 卡：DeepSeek-V3 级） |
|---|---|---|
| 装环境 + 标定 | 1 天 | 2 天 |
| 第一层 10–20 亿 token | 1–3 天 | 3–5 天 |
| 第二层 3 天日志 × 3 组（抽稀加速） | 约 1 天（分卡并行） | 2–3 天（串行） |
| +30% 余量 | 4–7 天（约 800–1,300 卡·时） | 10–12 天（约 1,900–2,300 卡·时） |
| 市场租价折算 | 0.5–1.2 万元 | 1.3–2 万元 |

假设：H20 BF16 148 TFLOPS / FP8 296 TFLOPS / 4.0 TB/s；预填充 MFU 稠密约 40%、MoE 约 25%；整机预填充 8B 约 3 万 tok/s、30B-A3B 约 4.5 万、A13B 1.1–2.3 万、DeepSeek-V3 级 FP8 约 0.8 万；"含开销" = ÷1.5（草稿评估 + 训练 + 读写）。日志输出需重新生成：中小 +0.5–1 天、大 MoE +2–3 天。第二层加跑 1 天真实时间：中小 +1 天、大 MoE +3 天。全量跑时第一层天数按上面总量表换算。租价：SMM 报价 H20 96G 服务器年约 3.9 万元/台/月（2026-09-07），H20 141G 含税 5 万元/台/月（2026-07-27）。

腾讯自有机器 → 现金成本≈0，代价是机器占 1–2 周。人：腾讯 1 人 1–2 周（取数脱敏、装环境、盯跑）；我方 1–2 周打包 + OSC 演练。启动到报告 4–5 周（中小第 4 周、大 MoE 第 5 周）。数据大概率不出腾讯 → 我方交脚本、腾讯跑、回传汇总表。

## 4. 故事

一句话：草稿模型会随流量变旧；推理服务闲时用自己的流量把它养新、忙时让路、不划算时关投机——腾讯三个月真实流量、H20 上同样机器多 X% 吞吐，不加卡、不改输出。

1. 问题是真的：量出现网头变旧速度（三个月降幅、产品线差异、换代当天降幅）。方法不赢也有用（定重训频率）。
2. 自己养自己管用：在线头 > 固定头、≥ 定期重训；变化后几小时追上；无标注、无专用训练卡、占空比 5–10%。
3. H20 更需要开关：算力约 H100 的 1/7、带宽略高 → 投机划算区间窄。屋顶线粗算：8B 稠密 k=3 在 H20 上并发超过 15–30 路转亏（H100 实测 128–256 路之间）；MoE 区间宽、可能常开，价值在训头。
4. 换成钱：同 SLO 吞吐 +X% → 少用 X/(1+X) 的机器；+10% ≈ 少 9%，每 100 台一年约 425 万（3.9 万/台/月）。

论文角度：补上 demo 两个弱点（公开数据造的流量、只有 H100）。

备用叙事：固定头不怎么掉 → "换代追得快 + H20 开关"；H20 高峰本该关 → 开关为主、训头为辅（同中文场景：关投机 +88%、训头 +12%）。

## 5. 判据（门槛可与腾讯商量）

| | 问题 | 通过线 | H100 参照 |
|---|---|---|---|
| R1 | 会变旧吗 | 三个月降 ≥5%，或产品线间差 ≥10%，或换代日降 ≥15% | 无，待量 |
| R2 | 在线头更好吗 | 平均接受长度比固定头 ≥+5% 且不输定期重训；变化后 ≤6 h 追到新稳态 90% | 出厂头换领域 +14–25% |
| R3 | H20 真机吞吐 | 同 SLO ≥+5% 有用、≥+10% 好；p99 不变差、违约不增 | 稠密 8B +11–18%、MoE +5–8% |
| R4 | 第一层换算可信吗 | 预测与第二层实测差 ≤3 个点 | 预测 +26%、实测 +24% |
| R5 | 安全 | 贪心逐 token 一致；回放全程热替换零失败；导出开销 ≤2% | 换头 0.3–0.9 s、开销 1.4% |

R2+R3+R5 过 → 建议小流量灰度。R4 过 → 以后评估新模型/新业务只跑第一层（几天、几千元）。
