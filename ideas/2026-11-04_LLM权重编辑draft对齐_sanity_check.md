# 用"权重空间编程"（GPT-6 直接改小模型权重）提高投机解码接受长度：sanity check

日期：2026-11-04。起因：用户贴来一份三道关验证方案（外部分析），问我怎么看。

## 1. 核实过的事实（MIT 博客，2026-11-02 发布，无论文）
- 作者 Takehi*、Teoh*、Zhang、Khattab，MIT CSAIL。"Sparks of Weight-Space Programming"。只有博客 + 日志仓库 RikiyaT/lm_understand-logs + HF 检查点 RikiyaT/Qwen3.5-0.8B-weight-space-programming（Apache-2.0，bit-exact diff，apply_edit.py 可重建）。编辑 harness 代码未公开，只给 prompt 里的规则。
- 实验 8：编辑者 GPT-6 Astra（Codex CLI，effort max），CPU numpy 内核，只有前向传播预算（10/25/50 次，每次 ≤512 题），禁止梯度。被编辑模型 Qwen3.5-0.8B（思考模式）。
- 修的是"思考循环"这一种病：追踪到第 15、19 层 MLP down_proj 写出的一个方向，从每层 64 个输出列里减掉它，共 131,072 个权重（0.016%）。
- 结果：MATH-500 7.9→48.1，撞 32K 上限 93%→33%，IFEval 21→62。练习题只用 GSM8K/MATH 训练集。
- 代价：三次运行各 74/86/158 轮、45–80 次 Python 执行、8.5/11.6/20.3 小时墙钟；未给 token 总数和费用。
- **没有任何基线**：没有 LoRA/微调/随机扰动/偏置校准对照。
- **唯一对照是 Gemma 3 270M**（本来不循环）：编辑完全无效（6.8→7.0–7.7）。原文结论："编辑能移走遮住能力的障碍，不能添加模型没有的能力。"
- 博客通篇不涉及投机解码、draft 或两模型分布对齐。

## 2. 判断：不看好作为方法；值得花 1 天做一个 ~1 GPU 小时的判生死实验

### 2.1 三条结构性理由
1. **投机解码不需要外科手术。** 权重编辑的全部卖点是"改 0.016%、保住其他能力"。而 SD 是无损的，draft 其他能力坏掉也不影响输出；draft 唯一的 KPI 是在服务分布上的接受长度。SD 要的是整体分布匹配，这正是梯度蒸馏最便宜、最擅长的事（specsched 的数字：3200 条在线更新 7 秒 GPU，接受长度 1.88→2.63）。方法的唯一优势在这个问题上一文不值。
2. **draft 与 target 的分歧不是"一种病"。** 同系列 0.5B 与 8B 的分歧主要落在知识/算力决定的位置（数字、推理分支点、高熵处），是"缺能力"，正是 MIT 自己的 Gemma 对照说明编辑不能补的那类。另外 SD 里 draft 每 ≤γ 个 token 就被 target 的前缀重新锚定，draft 自己长轨迹上的循环病几乎不会出现在接受过程里。
3. **成本倒挂。** 一个候选 = 一次 8–20 小时、上百轮 GPT-6 max 的运行；方案里 20 个候选 = 数周 + 几乎肯定超过 $100 的编辑者费用（按规则须先问）。同数据的 LoRA 蒸馏是几分钟。

### 2.2 新颖性状态
- 搜索未见"LLM 直接编辑 draft 权重"的先例；博客 2 天前才发，窗口存在。问题不在窗口，在先验。
- 强基线：DistillSpec、Online SD、Draft-OPD（2605.29343，on-policy 蒸馏）；"便宜适应 draft"的直接竞品：EDA（2603.09527，少参数把 draft 适应到微调后的 target）。理论：When Is a Draft Accepted（2606.30265）。

## 3. 对贴来方案的修改意见
对的：三道关、按题划分、封存测试只开一次、随机扰动 + 偏置校准 + LoRA 蒸馏三对照、GPU 时间与编辑者费用分开报。

要改：
1. **"固定前缀一致率只是诊断、必须让 draft 自己生成"在 greedy 下不成立。** target 固定 + greedy 时，被接受的 token 恒等于 target 的贪心轨迹，所以 draft 永远在 target 轨迹的前缀上出题。令 a_t = 1[draft 在 target 轨迹第 t 位的 teacher-forced argmax == target token]，则每轮接受数 = min(γ, 从该位起连续 1 的长度)，整条轨迹的接受长度分布由 a_t 序列**精确确定**。意义：编辑循环里评估任何候选只需一次 draft teacher-forced 前向（秒级），零次 target 调用；随机扰动对照可以免费重复上百次。要保留的告诫是：别用平均一致率，要用游程统计。封存测试仍真跑一次完整 SD，核对模拟值并测 tokens/s。
2. **先量"空间"再请编辑者。** 下界 = 闭式输出偏置校准（不请 LLM），上界 = 同数据 LoRA 蒸馏（验证集早停）。编辑者可能的收益夹在两者之间。两个端点各几分钟。若上界−下界 < 10% 相对，编辑者没有东西可找，直接停。
3. **"禁止梯度"定义不清。** 用 numpy 对 lm_head 做最小二乘就是换名字的训练。照 MIT 的做法用预算定义约束：前向次数、CPU-only、≤2 模块、≤权重比例。
4. **门槛改成相对 LoRA。** 封存集相对原始 draft +10% 且 bootstrap 下界 >0 只是"有效"；要算"值得采用"须 ≥ LoRA 蒸馏收益的 50% 且总成本不高于它。达不到就只是 finding，而用户 9/25 定的规则是不做 finding 为主体的论文。
5. 随机扰动对照要同稀疏结构（同两模块、同 64 列模式、同范数），≥20 次重复。
6. 模型对：若要复用 MIT 检查点，用 Qwen3.5-0.8B → Qwen3.5-9B（或 4B）；先实际核对 tokenizer、特殊 token、聊天模板一致（二手来源说全家 248K 词表，未见官方确认）。思考模式下 greedy 容易循环，输出上限固定 2048；target 若也大量循环就改非思考模式，两个 draft 共用同一 target 轨迹所以比较仍公平。第一轮用 HF 手写 greedy 验证循环（需要逐位日志），不依赖 vLLM 是否支持独立 draft。

## 4. 我会做的顺序（总计 ~1 天、~1–2 GPU 小时，OSC）
- Rung 0（免费数据点）：MIT 编辑版 0.8B vs 原版 0.8B 作为同一 Qwen3.5-9B target 的 draft，256 道数学题 greedy，a_t 序列 → 模拟接受长度 + 首拒位置分布。预测差异 ≈ 0。顺带检验"首拒位置上 draft 提议的是最近 n-gram 的重复"占比有没有下降。
- 关一 + 关二诊断：原始 draft 的接受长度与首拒位置分布；首拒 token 分类（格式/LaTeX/结束符/数字/推理分支词/其他）。预门槛：若前 50 个（token 类型 × 上下文类）桶覆盖不到 40% 的首拒，分歧是弥散的，停。
- 两个端点：偏置校准、LoRA 蒸馏（128 题 target 轨迹，验证集早停）。算"空间"。
- 只有空间 ≥10% 且分歧集中时，才估编辑者费用并请示，再跑编辑循环。

## 5. 结论
先验 80% 以上：最终排序是 编辑 ≤ 偏置校准 ≪ LoRA 蒸馏，不成论文。可能的残值是一个诊断结论（draft 分歧有多少是可校准的格式项、多少是弥散的能力项），只能做别的工作的动机或消融。唯一方法形状的衍生物是"推理服务器内、只用前向的闭式 draft 校准"，与 GPT-6 无关，且需单独查新。

## 6. 用户澄清（同日）："我的意思是如果能通过大模型改小模型权重，提高准确率"
理解为：让 target（大模型）去改 draft（小模型）权重，把 draft 变准，从而接受更多。判断不变，理由收紧为三条：
1. **无损 SD 里"准"不是 draft 的目标，"像 target"才是，两者脱钩。** Judge Decoding（ICLR 2025 oral, 2501.19309）：GPT-4o 当 draft、甚至人写文本在标准验证下接受率都不高，验证看的是对齐不是正确；EAGLE 头单独零准确率但接受长度超独立 1B draft；DistillSpec：对齐 target 输出 > 正确答案 SFT。MIT 编辑本身是最干净反例：准确率 8→48 来自"不再循环撞上限"，改一个循环方向，target 的不循环前缀上下一 token 行为几乎不变 → 预测接受长度不动。能力型的"准"（换 2B）有用但那是换 draft 不是编辑。
2. **大模型教小模型已有免费且最直接的通道**：验证时 target 在每个草稿位置算完整 logits（Online SD / Aurora / specsched live tap）。"读写权重"是用贵且间接的通道传同一份信息。
3. **能力**：博客只用 GPT-6 Astra（effort max、Codex、74–158 轮、8–20 h），未测任何更弱编辑者；8B target 做不了；target 是前沿模型时成本更压不过 KD。
唯一"draft 更准"真有价值的地方 = 有损/级联投机（Faster Cascades via Speculative Decoding ICLR 2025, 2405.19261；Judge Decoding），但"怎么变准"与投机无关，两件事拼接无化学反应且线挤。
**Rung 0 改标签**：直接检验"准确率 8→48%、其余不变的 draft，接受长度动不动"；加 Qwen3.5-2B draft 作能力型参照。预测：编辑版 ≈ 原版 ±2%，2B 明显更高；编辑版 >+5% 则认错再谈。

## 9. "第三模型定向编辑"假设：修复一类分歧的乐观上限（2026-11-04 深夜，仅 CPU 回放，bound_analysis.py）
用户贴来第四份外部分析：三模型分工（draft 起草 / target 验证 / 第三模型按验证记录离线编辑 draft），指出已跑实验测的是"让 0.8B 数学更好"而非"让 0.8B 更容易被 9B 接受"，建议先用已存轨迹做乐观上限：某类分歧全部修对、其余不受损，按 γ=5 重算。我同意这是不同假设，并直接算了（诊断 128 题排序、留出 128 题报告）：
- 天花板（全部分歧修对）+36.6%；上限 ≈ 36.6% × 该类覆盖的分歧比例，**没有任何一类性价比突出**（修一个位置延长的游程期望与类别无关）。
- 前缀可识别的大覆盖类都是"draft 没把握的下一个词"：提议是词 59% → +21.3%；p_top<0.5 且提议是词 41% → +14.5%；p_top∈[0.3,0.5] 38% → +13.2%。这是通用能力，不是局部故障。
- 唯一故障型的类：复制型提议 18.5% → 100% 修对 +5.5%、修对一半 +2.7%；循环型 12.6% → +3.8% / +2.0%。MIT 的去循环编辑在这类上实得 ≈0。
- 参考：近失 p_tgt≥0.5·p_top 43% → +15.0%；换 2B 实测 +9.5%（修对 46% 的分歧但也弄坏一部分）。
**判定**：按该分析自己的判据（"连上限都很小就省掉第三模型实验"），第三模型定向编辑实验不做。编辑者能定位的故障型类上限 < +5% 门槛（在 100% 修对的离谱假设下才 +5.5%）；能过门槛的类等于"让 draft 整体更聪明"，那是蒸馏/换大 draft 的活。线上实时版（后台积累拒绝、定期发布）本质是把 specsched 的训练器换成 LLM 编辑者，必须在同成本下打过验证 logits 上的梯度训练，看不到路径。
文件：runs/r0/bounds.{md,json}；Excel 加"乐观上限"页（5 页）。

## 10. 外部建议"下一步做动态草稿长度调度"（同日，第五份）：判不做，已有数据回放即可收口
建议内容：按前缀决定每轮起草几个 token，先量实际成本（9B 单独 / 0.8B 起草 / 2B 起草 tokens/s），再用 CPU 算 oracle DP 上限 vs 验证集最优固定 γ，上限够大才做可部署规则。
- **方向已被占，且用户自己 8-31 已判死过相邻方向**（[[project_specdecode_novelty]]：负载感知投机长度四维全 scooped：MoESD、TurboSpec、vLLM Adaptive Verification 已合并、SGLang DP 同步 K）。按前缀/置信度决定起草长度这一支同样满：SpecDec++(2405.19715 训练停止头)、AdaEDL(2410.18351 熵阈值免训练)、SVIP(2411.18462 草稿熵)、DISCO(2405.04304 分类器)、GammaTune(2504.00030)、PEARL(2408.11850 并行起草免选 γ)、BanditSpec(2505.15141 在线 bandit 调 γ)；vLLM 自带按 batch size 的静态 γ 表（specsched 已用）。
- **oracle 上限已用 Rung 0 数据算完（gamma_oracle.py，runs/r0/gamma_oracle.{md,json}）**：成本模型每轮 γ·r+1（r=起草/验证成本比），固定 γ 在 1–8 按同一 r 取最优。0.8B：oracle(γmax=8) 比最优固定省时 10.6%(r=0.05)–22.8%(r=0.3)，γmax=16 时 23–30%；2B 类似 8–19% / 21–29%。一致游程均值 9.46、中位 4、≥8 占 34%。这与文献里前缀可见规则实际拿到的 10–20% 同量级 → 没有新的研究问题。
- **2B 不值得（回答其第 1 步，无需 GPU）**：2B 只在每 token 起草成本 < 0.8B 的 1.17–1.59 倍时才赢（盈亏点随 r 变化），实际权重 2.5 倍、小 batch 访存受限 ≈ 2.5 倍成本 → 任意 r 下 0.8B 的固定 γ 都更快（r=0.1：3.34× vs 2.24×）。
- 口径限制：单序列时延、验证成本与 γ 无关、greedy；用户主线（specsched）的高并发区间里决定收益的是批级 γ/开关（frontier），不是逐序列动态长度。

## 11. 用户决定继续做投机解码权重编辑 → 按其方案做定向替换规则筛查（2026-11-05 凌晨，CPU，pair_screen.py，两折交叉）
方案：①在 0.8B≠2B 的位置按有向 (a→b) 统计 9B 实选 b/a/其他（修好/弄坏/仍错）；②拿掉 2B，在所有 0.8B 提议 a 的位置找简单前缀规则（前 1/2 个 token、上下文集合、置信度、组合）；③冻结规则在留出题强制替换回放 γ=5，对照"总是替换"。
- ①净收益可观但都以"2B 恰好选 b"为条件：`\n`→`\n\n` +130（91 题）、`$`→`$.` +56、` Wait`→` The` +38/0 弄坏、` Wait`→` Let` +33/1。两折前 20 对高度重合。
- ②③拿掉 2B 后，40 个最优对里只有 10–11 个能找到诊断集净值为正的规则，支持数多为 8–30；留出集合并回放 **+0.03%（折 1）/ +0.01%（折 2）**，事后只留留出集仍为正的规则也只有 +0.05%/+0.04%；"总是替换"对照 **−19.4%/−30.8%**；"只在 2B 也选 b 时替换"参考 +0.44%/+0.35%。连最像病的 ` Wait`→` The`（p_top<0.5 时）留出集也是 70 修好/67 弄坏。
- 对级替换天花板（诊断集 548 个正净值对、触发条件完美）：**+10.6%/+10.3%**，数值与换 2B（+9.5%）接近；数值接近不能推出两者利用的是同一种知识。
- 为什么跨折稳定的候选表仍给不出可靠的修改目标：换行符两个方向都在“赚钱”——`\n`→`\n\n` 净修好 130，反向 `\n\n`→`\n` 也净修好 53，赚不赚取决于具体是哪一次换行；一律替换则 −19.4%/−30.8%。
**判定**（按方案自己的判据）："收益一拿掉'2B 恰好选了 b'就消失 → 找到的是 2B 的预测优势，手头没有能交给 0.8B 的修正规则"。候选替换找到了，但能在新题上产生实质收益的触发条件没有找到。
**结论范围（2026-11-05 按用户意见收窄）**：实验支持的是"测试过的短前缀与置信度规则没有提取出可用信号"；"只有看到完整上下文的模型才能判断"是推断，不是实验结论。若用 9B 的选择作标签训练一个决定是否替换的小判别器，可称为受教师监督的路由/校正，是否算蒸馏取决于训练方式；且即使判别器成功，仍需另做实验才能证明这种判断能通过局部权重编辑写进 0.8B。决策：**本线维持 CLOSED，不再用这 256 题训练判别器**。Excel 第 7 页"定向替换筛查"。
