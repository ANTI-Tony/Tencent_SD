# SGLang 移植（2026-10-28 起，论文"第二个引擎"）

用户 10-28："sglang也做了"。目标：把 vLLM 研究的三个引擎机制移植到 SGLang，原样复用冻结的 harness / 控制器 / 训练器 / 提示文件 / 种子，在 SGLang 上单独校准、单独冻结 checkpoint，跑缩小版矩阵（5 策略 × 3 场景 × 3 次 = 45 次），写进论文单独一节。DeepInfer 判不可行（只支持 DeepSeek-V4.1-Flash、SM100/昇腾，内置 MTP，没有外挂草稿模型、在线训练和热替换）。

## 1. 环境与默认路径

- `/fs/scratch/PCS0296/specsched/env/sgl0510`：sglang 0.5.10.post1（PyPI 最新），torch 2.9.1+cu128，sglang-kernel 0.4.1，flashinfer 0.6.7.post3，transformers 5.3.0；freeze 在 `env/sgl0510_freeze.txt`。只有服务器进程用它；harness、基准客户端（`vllm bench serve`）、控制器、训练器仍在冻结环境 ss312。
- SGLang 默认 EAGLE-3 路径 = spec v1，**投机时 overlap 调度器关闭**（spec v2 是实验特性，未用）。注意力后端 fa3，page size 1，chunked prefill 8192。
- 服务器参数与 vLLM 对齐：256 并发、上下文 4096、关前缀缓存、种子 0、模型名 target、EAGLE-3 链式 k=3（topk 1、验证 4 个 token）、CUDA graph 到 batch 256。另加 `--disable-piecewise-cuda-graph`（见坑②）。
- 显存：vLLM 的 `--gpu-memory-utilization u` 管整个进程；SGLang 的 `--mem-fraction-static` 只管权重 + KV。映射 `mem = u − 非静态显存 / 总显存`，非静态显存实测（C=256 后 nvidia-smi 峰值减静态池）：8B 有草稿 7.22 GiB、无草稿 1.14 GiB；MoE 5.65 / 0.80 GiB → 取 8.0 / 1.75 / 6.5 / 1.25 GiB（`sgl_common.NONSTATIC_GB`），保证服务器峰值、也就是留给训练器的显存与 vLLM 运行一致。

## 2. 移植了什么（`code/specsched/sgl/specsched_sgl.py`，运行时补丁，不改安装包）

用 `python -m specsched_sgl_launch` 启动 SGLang；SGLang 用 spawn 启动调度器 / 反分词子进程，子进程会重新导入这个模块，所以补丁在每个进程里都生效。

| 机制 | vLLM（冻结的 6 个补丁文件） | SGLang 移植 |
|---|---|---|
| 实时导出（tap） | 模型 runner 把每个已提交位置的 (token, aux 隐状态) 写进 /dev/shm 环形缓冲 | 同一格式、同一环境变量、同一读取端（复用 `livetap.py` 的写线程）；行 = 预填充块 + 每次验证被接受的前缀（待定 token + 被接受的草稿）+ 关投机时每步的输入 token；调度器看到请求结束后写 FINISH |
| 草稿热替换 | `reload_draft_weights` collective RPC | 从 `<路径>/model.safetensors`（或出厂头的 pytorch_model.bin）原地拷贝进草稿模型，跳过 embed_tokens（目标模型的）；原地拷贝保持 CUDA graph 有效 |
| 投机开关 | `set_speculation`：关时不提议草稿、不跑草稿模型，下一步生效 | 关时目标模型用启动时额外捕获的一套普通 decode CUDA graph（独立注意力后端实例）跑，记账等同"接受 0 个草稿的验证"；草稿模型完全不跑（与 vLLM 同）；重新打开后的第一步用按请求槽位缓存的 aux 隐状态做一次 draft-extend 补算草稿输入；关闭期间新解码位置的草稿 KV 保持陈旧（与 vLLM 同） |
| 指标 | vLLM 自带 /metrics | 自己的 /metrics，用 vLLM 0.27.1 的指标名（运行中 / 排队请求数、生成 token 计数、草稿数、接受数、抢占数），数值由调度器写进共享内存块 |
| RPC 入口 | `VLLM_SERVER_DEV_MODE=1` 的 /collective_rpc | 自己的 /collective_rpc；HTTP 进程写 /dev/shm 邮箱，调度器每轮循环检查、在两个 batch 之间执行 |

包装脚本（冻结 harness 一行没改，全部"导入原文件 + 换函数"）：`hotswap_run_sgl.py`（换 start_server，控制器加 `--model-json sched/model_sgl_<m>.json`；`--tide` 走 TIDE 式）、`sgl_calib.py`（原样复用 c1_run / frontier_run，输出 runs/sgl/，c2 学习曲线头和训练器缓存软链复用）、`abl_matrix_sgl.py`、`sgl_port_check.py`、`sgl_freeze.py`。复用的冻结文件（控制器、训练器、harness、c1_run、frontier_run、livetap、head 等）哈希与 vLLM 冻结记录逐个一致。

## 4. 速度：关投机这一步有多贵（`runs/sgl_check/<m>/perf`，代码提示，输出 ≤ 512）

8B，tok/s：

| C | 投机开 | 投机关（定版） | 投机关（初版：关时草稿每步续算） | 普通服务器（关 overlap） | 普通服务器（默认） |
|---|---|---|---|---|---|
| 1 | 188 | 111 | 101 | 115 | 117 |
| 16 | 1874 | 1254 | 1197 | 1360 | 1341 |
| 64 | 5503 | 3941 | 3641 | 4093 | 4314 |
| 256 | 10538 | 9430 | 8857 | 10000 | 11152 |

- 初版让草稿模型在关闭期间每步吃进新 token（为了随时无缝打开），C=256 比普通服务器慢 20%，比开着投机还慢 16%——开关失去意义，于是改成 vLLM 的语义（关时草稿完全不跑、重开时补算一次）。
- 定版在 C=256 仍比普通服务器慢 15%：约 10 个百分点是 SGLang 带草稿时不能用 overlap 调度（普通服务器关掉 overlap 也只有 10000），约 5 个百分点是移植路径本身（投机路径的记账、重复的结束检查等）。vLLM 里关投机 ≈ 普通服务器（`runs/switch/m1_code_v2`：C=256 关投机 15459 tok/s，比开着高 10.5%）。
- 结论：在 SGLang 上，运行时开关的"关"状态比单独的普通服务器差一截；8B 代码饱和时开着投机（10538）仍比关掉（9430）快。**所以 SGLang 校准里的 S0 定义为"投机服务器关掉投机"**（运行时 z=0 实际得到的速度），独立普通服务器只作为 Plain 基线。

MoE（mem 0.82），tok/s：开 259 / 1181 / 2556 / 6729；关 171 / 736 / 1705 / 3803；普通服务器 185 / 766 / 1833 / 4274。MoE 上投机在 C=256 仍有 1.77 倍，和 vLLM 研究里"MoE 关投机吞吐减半"一致。

未打补丁的冒烟（`runs/sgl_smoke/m1`）：投机 C=1/16/256 = 187/1860/10304，普通 117/1340/11046；补丁在投机开时没有可见开销（188/1874/10538）。

## 5. 坑

1. **home 配额满导致卡死**：tvm-ffi 的 JIT 内核编译把锁文件放在 `~/.cache/tvm-ffi`，home（PFIN0007）已满，建锁失败后无限重试，表现为卡在 CUDA graph 捕获、GPU 0%。用 py-spy 定位。修：`sgl_common.SGL_CACHE_ENV` 把 TVM_FFI_CACHE_DIR / SGLANG_CACHE_DIR / SGLANG_DG_CACHE_DIR 指到 scratch。
2. **无草稿服务器启动即崩**：SGLang 0.5.10 在没有草稿时默认开实验性的分段 CUDA graph（预填充用 torch.compile），这里启动即非法访存（FusedAddRMSNorm）。所有服务器加 `--disable-piecewise-cuda-graph`，投机和普通服务器的预填充走同一条路径。
3. SGLang 对 chat 请求默认使用模型 generation config 的采样参数；基准客户端显式给 temperature 0，不受影响。

## 6. 顺带发现（与 SGLang 无关，已改论文措辞，未推送）

vLLM 0.27.1 没有 `vllm:time_per_output_token_seconds` 这个指标（只有 inter_token_latency 和 request_time_per_output_token），冻结控制器读它时一直拿不到，`tpot_meas` 始终为 None，所以所有实盘运行里控制器用的 TPOT 都是校准模型的**预测值**（T_base(C)/Ĝ/(1−κd)），不是实测值。论文 method.tex 的"读取过去一秒的平均 TPOT"、"T_0 是实测 TPOT"、算法 1、策略表和图 2 已改成"预测"，两版编译通过、正文仍 8 页。

**(3) v7.1（runs/abl_v71，15 次）负结果**：前沿截距改为 regime 内成对实测 + 盈亏点附近关探测 + 1–4 轮前瞻。代码 vs v6 −1.6±3.8（r1/r3 关探测后 20–25% 的 B 段关着投机、6 次换头）、vs Informed −3.1；code+chat vs Switch −6.6±1.1（7–10 轮、投机开 32–60%）；zh+chat −2.4；MoE +1.4。根因：切换瞬态把接受长度的长 EMA 初始化偏了，16 s 后判成漂移 → regime 重置 → 后验清零、导出节奏重来；再加探测/切换代价本身 ≈ 它能学到的 1–2%。不出 v7.2。c0818 节点坏（两次吞吐 1/3），挪开重跑。

**结论**：在这些负载上，只要投机由前沿开关决定、不在天花板过不了的域上训，训练规则怎么定（校准预算 / 校准价值规则 / 无校准一步规则）都在彼此 1–2% 内；在线测前沿的代价超过收益。调度可挽回的空间 ≈ κd ≈ 2%，与两份外部评价的估算一致。论文定位应为测量 + 系统（+ 无校准变体与负结果如实报告）。段长 × 预算 kill test（99 次）在跑。

花费：v7.0 15 + v7.1 15 + budget 15 + 冒烟 2 + 补跑 3 ≈ 50 次 ≈ 10 GPU·h ≈ $1.4。
